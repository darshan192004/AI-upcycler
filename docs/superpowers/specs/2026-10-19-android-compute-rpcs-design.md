# Android Worker Compute RPCs — Design (2026-10-19)

Status: **SPEC — awaiting review** (epic: tasks.md §5 "Port the engine to the
Android worker", first half). The mTLS/QR pairing worker half is spec'd and
shipped separately afterwards; this epic deliberately excludes it.

Predecessors: `2026-10-16-worker-engine-design.md` (the Rust engine this one
mirrors) and `2026-10-18-live-chat-path-design.md` (the serving path that
becomes cluster-real once the phone joins).

## Intent

Make phones actually *compute*. Today the master's half of the split is real
and shipped (`LoadedPipeline` drives `Handshake` → `LoadLayers` →
`ExecuteForward` → … → `UnloadLayers` over `proto/cluster_rpc.proto`, proven in
`core/tests/distributed.rs` and live two-stage parity PR #63), and the Android
worker answers the two metadata RPCs — but its compute RPCs surface
`UNIMPLEMENTED` (`WorkerRpcService`, lines 23–31), so the master never places a
stage there. This epic ports the Rust engine's contract to the Android worker:
real GGUF layer-range loading, real Qwen2-family forward math, real session KV
cache — behind the exact same wire contract, so `LoadedPipeline` can drive an
Android stage unchanged **except** for transport, which remains plaintext until
the pairing epic (recorded honestly; same as the local Rust worker today).

tasks.md line 77 currently reads "cross-compile native C++ `llama.cpp` RPC
worker server for ARM64 (`libllama-rpc.so`)". That wording predates the
2026-10-16 spec and is **superseded by it**: llama.cpp's own distributed RPC
backend was considered and rejected (it replaces, not joins, our
`WorkerService` contract, and master-side sampling D2 semantics don't go
through it). This epic's PR corrects the checklist wording.

## Decisions (D-A1…D-A6)

### D-A1 — Pure-Kotlin engine port; JNI/Rust deliberately deferred

The engine is ported to Kotlin, mirroring `worker/src` module-for-module:
`gguf` (reader exists as shared crate `model-io`; Kotlin mirrors the parsing
invariants), `quant`, `math`, `layers`, `engine`. Not llama.cpp's rpc-server
(rejected above), and not a Rust/JNI `.so` as the first implementation:

- No NDK anywhere today: local machine has none; CI's Android lane is a plain
  JDK 17 + SDK box (`.github/workflows/android-worker.yml`) with no Rust.
- A native `.so` cannot load on the `testDebugUnitTest` JVM lane (wrong arch),
  which would gut the project's established device-free proof vehicle.
- The Kotlin port is testable end-to-end on plain JVM, reuses the committed
  golden fixtures, and adds **zero new dependencies** (scalar math only).

The measured follow-up ("if on-device latency from pure-Kotlin float loops is
unacceptable, move the hot loops to a native lib behind the same parser/engine
interface") is recorded — measuring it requires a device, so deciding it now
would be speculation.

### D-A2 — Bit-exact parity vs the Rust engine is the proof

The tests consume committed fixtures with a **single source of truth** inside
the Android test resources, `mobile-worker/android/app/src/test/resources/engine/`
(regenerated byte-identically by the Rust `fixture_dump` example, which writes
straight into that directory; outputs never hand-edited):

- The four existing dequant goldens (`worker/tests/goldens/*.txt` — kept where
  they are, PR5 evidence untouched) are copied into `engine/goldens/`; the
  Kotlin dequant must match them **exact bit equality**, same records, same
  corruption-refusal behavior. A gradle task `checkEngineFixtureSync` is the
  drift guard (proto-guard pattern): the copies must stay byte-identical to
  the Rust originals.
- Deterministic tiny GGUF files (the `model-io::fixture` writer: hidden 64,
  ffn 128, vocab 256, ctx 64, xorshift32 weights; a F32-untied + tokenizer-KV
  variant, a tied Q4_0 + QKV-bias variant, and a Q5_1-refusal variant) commit
  under `engine/fixtures/`, and forward input/output vector files cut from the
  **Rust engine** join them as f32-bit-pattern text (same format as the
  dequant goldens). Coverage: stage-0 prefill + decode, mid-stage forward,
  head-stage forward, and the refusal matrix (bad range, wrong shape,
  out-of-order `sequence_position`, unsupported quant type id 7).
- Bit-exactness is the bar where it is honestly attainable: **dequant**, the
  byte accounting, and every ordered multiply-accumulate are pure bitwise
  deterministic and pinned exactly. Forward *outputs* additionally cross one
  libm boundary (`powf`/`sinf`/`cosf`/`expf` in RoPE/softmax/SiLU differ by
  1–2 ulp between MSVC, glibc and fdlibm even among Rust hosts), so those
  comparisons use a strict, documented tolerance (relative ≤ 1e-5, about
  2 ulp of the typical value range) against the Rust-cut vectors — with the
  tolerance named, bounded, and justified in the test file itself, never a
  blanket epsilon. The route to full bit parity (porting one fdlibm
  `expf/sinf/cosf/powf` family to both engines) is recorded as a follow-up,
  not silently dropped.
- Both sides consume the same fixtures: Rust side pins them as regression
  guards (a Rust test reads the committed vectors back), the Kotlin engine must
  reproduce them bit-for-bit (same IEEE-754 ops in the same order — achievable
  because both engines are ordered scalar loops; Kotlin `f32` = Rust `f32`).
- Gradle exposes `fixtures/engine/` to the JVM tests via
  `sourceSets.test.resources.srcDir(rootDir.resolve("../fixtures/engine"))`
  (path adjusted to actual depth). Kotlin reads them as classpath resources.

Bit-exactness is the bar, not epsilon tolerance: anything an epsilon would
hide in a dequant table or an accumulation-order change is exactly the drift
the split cannot afford.

### D-A3 — Mirror the Rust engine's contract exactly

`mobile-worker/android/.../engine/Engine.kt` implements the same state machine
as `worker/src/engine.rs` — validation order, refusals, and success shapes
identical (the master's expectations are pinned in `core`):

- `LoadLayers`: model_id must match the file's `general.name`; range check
  `0 ≤ start ≤ end < block_count`; refuse a second load without unload;
  ownership rule — `token_embd.weight` iff `start == 0` OR (file tied AND
  range ends at the last block); per-layer `blk.{i}.*` required/optional
  tensor lists identical to the Rust sets; dequantize at load to materialized
  F32; `allocated_ram_bytes` = F32 bytes; refusals return
  `success:false + error_message` (no gRPC error), exactly as the Rust
  `refuse` closure does.
- `UnloadLayers`: model_id mismatch → `success:false`; never-loaded unload →
  `success:true` with `freed_ram_bytes: 0` (master rollback never sticks);
  drops sessions with the range.
- `ExecuteForward`: FP32 activations only; stage-0 shape `[1, n]` (token ids,
  validated as integral/in-range), later stages `[n, hidden]`; `start_layer /
  end_layer` must equal the loaded range; `sequence_position ≥ 0`, must equal
  the session's cached length, and must fit `context_length`; session cap
  (16, same as `MAX_SESSIONS`); KV caches sized `kv_dim × context_length`;
  head stage = loaded range ends at the last block → RMSNorm + lm head
  (`output.weight`, or tied `token_embd.weight`); output tensor shape
  `[n_tokens, out_len]`, `execution_time_us` real.

Memory honesty comes free: because D-A3 mirrors the materialize-at-load
policy, `Handshake`/`GetHealthStatus` free-RAM readings plus
`allocated_ram_bytes`/`freed_ram_bytes` keep the master's planner fed with true
phone numbers (the planner already plans around reported RAM —
`planner_splits_between_two_ram_limited_nodes` pins that).

### D-A4 — Engine presence is optional; provisioning narrative is honest

No model file on the phone → no engine; compute RPCs keep surfacing
`UNIMPLEMENTED` (the current, honest state — never schedule work the node
cannot honor). When a side-loaded GGUF appears under the app's filesDir (this
epic's provisioning story: `adb push` or a document-picker path, whichever
serves the pairing demo), the engine constructs at startup and the compute
RPCs answer. `LoadLayersRequest.weights_chunk_data` stays empty (master-side
`build_load_request` keeps that contract, pinned by an existing `core` test);
cross-device weight push is a proto-reserved follow-up, not this epic.

### D-A5 — Zero proto change

`proto/cluster_rpc.proto` stays byte-identical (D6 carries over from the chat
epic; the compute RPCs are already fully defined and used). `checkProtoInSync`
keeps gating the vendored Kotlin copy.

### D-A6 — Epic edge

This epic ends at the extended `WorkerRpcContractTest`: the real Kotlin engine
behind the real `WorkerRpcService`, driven over in-process gRPC through the
generated stubs — the compute RPCs answer a real split of the tiny fixture,
and the refusals land as honest `success:false`. Plus the slower integration
slice (if CI proves receptive): the *Rust* `LoadedPipeline` on loopback
dialing the Kotlin worker binary running as a JVM process with the same
fixture (both to be proven device-free). On-device serving, mTLS/QR pairing
(tasks.md §5 pairing line), thermal telemetry values, and a live split across
actual phones are **out** — hardware-gated or next-epic.

## Commands

Android (from `mobile-worker/android/`, wrapper both locally and on CI):

- `./gradlew --no-daemon checkProtoInSync` — proto drift guard.
- `./gradlew --no-daemon :app:testDebugUnitTest` — the device-free proof lane.
- `./gradlew --no-daemon :app:assembleDebug` — APK builds after the change.

Rust (fixture regeneration, from repo root; never hand-edit the outputs):

- `cargo run -p ai-upcycler-model-io --example fixture_dump --
  mobile-worker/android/app/src/test/resources/engine/fixtures` — rewrites
  the committed tiny GGUFs byte-identically from the deterministic writer.
- The forward vectors are cut by a companion debug/example target in the
  `worker` crate (added with S4) that drives `WorkerEngine` on the tiny
  fixtures and overwrites the committed text files.
- Variant wrapper for local Rust work: the established `cmd /c "set
  CARGO_TARGET_DIR=D:\ai-upcycler-target&& …"` pattern; no MSVC claims — the
  engine rebuild runs test-only.

    Gguf.kt      — GGUF-v3 header/metadata/tensor-descriptor reader

Nothing in `core/`, `worker/`, or `proto/` changes except Rust tests/additions
that cut and pin the fixtures (a new `worker/tests/forward_parity.rs` reading
the committed vectors). The gradle build gains the `checkEngineFixtureSync`
drift guard next to `checkProtoInSync`.

## Testing Strategy

- **Structural (Rust)**: `worker/tests/forward_parity.rs` replays the
  committed vectors against a fresh engine over the same committed fixture
  bytes (single source, no regeneration step) and asserts they match at the
  D-A2 amendment's tolerance — pins the Rust side so a later Rust edit that
  changes outputs fails loudly *before* the Kotlin copy hides the drift.
  Bit-exact on the cutting host; the tolerance exists for cross-libm
  replay hosts.
- **Dequant (Kotlin)**: the four golden record files, exact bit patterns.
- **Engine (Kotlin, `WorkerRpcEngineTest`)**: full refusal matrix (unknown
  model, bad range, double load, missing tensor, unsupported quant type id 7
  via the fixture's `UnsupportedQ5_1`, wrong shape/dtype, out-of-order
  session, token-id-above-vocab, context overflow, session cap, second stage
  of an unloaded range) + load/enumerate/unload byte accounting.
- **Forward parity (Kotlin)**: equality against the committed vectors at the
  D-A2 amendment's bar — forward outputs relative <= 1e-5 (~2 ulp, one libm
  boundary), inputs/shapes bit-exact — for stage-0/mid/head, prefill and
  decode positions, tied and untied variants (incl. a full range over the
  Q4_0-tied fixture so dequant feeds real matmuls).
- **Wire (Kotlin, extended `WorkerRpcContractTest`)**: real engine + real
  service over in-process gRPC; the split of the tiny fixture loads, forwards
  handoff-after-handoff, and unloads like `core/tests/distributed.rs` does
  against its mock pair — now against a real other-side engine.
- **CI lane**: `android-worker.yml` unchanged (same commands); this epic must
  fit the existing lane, not grow toolchain surface.

## Boundaries

- **Always**: gradle unit tests + proto guard before every commit; conventional
  commits; per-PR reviewer-guide comment + resolution comment; honest claims
  only (the word "real" applies only to paths with evidence).
- **Ask first**: new gradle/deps changes (none expected), moving existing
  fixture files (only the copies under `fixtures/engine/` are new), touching
  `core/` beyond an honest comment if the Kotlin fixtures imply a doc fix.
- **Never**: modify `proto/cluster_rpc.proto`; fake a passing forward by
  shipping the Rust engine's output table as a lookup (the fixture drives the
  parser+math, never replaces them); claim device validation that did not
  happen; loosen a refusal that the Rust engine keeps.

## Success Criteria

1. `:app:testDebugUnitTest` green locally and in CI `android-worker`, with the
   new dequant/engine/parity/wire tests included and both `assert` styles.
2. `checkProtoInSync` green; `proto/cluster_rpc.proto` byte-identical.
3. The engine answers bit-identical forwards for the committed fixture across
   stage-0/mid/head and tied/untied/f32/q4_0 variants.
4. `WorkerRpcService` no longer surfaces `UNIMPLEMENTED` when an engine is
   configured; the contract test proves a full split lifecycle.
5. tasks.md §5 wording corrected and the compute-RPC item ticked with real
   evidence pointers; architecture.md §3.1 gains the Android note; this spec
   marked IMPLEMENTED with PR numbers.
6. The un-ticked remainder is honestly stated: mTLS/QR pairing worker half +
   on-device serving are next (hardware/next epic).
