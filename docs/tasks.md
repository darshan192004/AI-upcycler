> ⛔ Blocked in this environment: requires a physical 8 GB host plus 2× Android worker devices.

Both were mutation-checked. The page-faulting half still needs the physical 8 GB host.
- [ ] Perform security penetration audit on mTLS inter-node transport — **master side audited and complete**: found and fixed the certificate role-confusion (no `extendedKeyUsage`; a `serverAuth` certificate authenticated as a client). `NodeCa` now signs four identities — the master's server and client certificates and each worker's server and client certificates — each pinned to exactly one role, with adversarial tests (`server_cert_is_not_accepted_as_a_client_cert`, `client_rejects_server_cert_from_untrusted_ca`). The transport is no longer test-only: enrollment provisions both link directions and `EnrolledWorkerSource` is the production transport source, so `LoadedPipeline::load_secure` is reachable outside tests (covered in `core/tests/api.rs`, and the master never issues its own server identity to a worker). Remaining: no live caller passes that source yet and the worker's mTLS server does not exist (§5), so a full audit of a running cluster is hardware-gated.
